# 组件与状态

按正在处理的组件阅读。以下是判断方法，不是统一替换词库。

## 让动作对应真实结果

| 组件 | 要确认的事 | 可采用的表达 |
| --- | --- | --- |
| 导航 | 打开哪类内容 | “用量记录”，而非宣传语 |
| 文件操作 | 打开选择器还是执行导入 | 分别用“选择文件”和“导入” |
| 开关 | 开启后持续发生什么 | “自动备份”，状态交给开关表达 |
| 表单 | 输入后是否仍能知道字段含义 | 保留可见标签，示例放在提示中 |
| 暂停/继续 | 当前点击将执行哪个动作 | 播放时显示“暂停”，暂停时显示“继续” |
| 菜单 | 操作前是否还需要选择 | 依平台约定使用省略号，不给每个弹出视图都加省略号 |

先读标题和按钮，再读正文：忽略正文时是否会做出错误决定？重要信息若只能在辅助说明里找到，应调整层级。

## 失败不是一个状态

| 状态 | 文字的工作 | 能提供的恢复动作 |
| --- | --- | --- |
| 初次使用无内容 | 说明这里会出现什么 | 实际存在的添加入口 |
| 筛选无匹配 | 说明没有匹配当前条件 | 修改条件或清除筛选 |
| 已完成而列表为空 | 说明任务已经处理完 | 不强迫创建新任务 |
| 正在加载 | 表达进行中，避免暗示已成功 | 仅在支持时提供取消 |
| 已排队/待批准 | 说明还需等待什么 | 已存在的查看状态入口 |
| 保留旧值但更新失败 | 保留值、最后更新时间及失败范围 | 支持时重试该来源 |
| 权限被拒绝 | 指明受限功能 | 已实现且有效的授权或设置路径 |
| 只有部分来源成功 | 分别表达成功数据与失败来源 | 针对失败部分恢复 |

不要仅凭超时判定密码错误或网络断开。可以写“未能更新”，将具体诊断放入已有的详情位置。

## 有后果的选择

确认动作处理函数和数据归属之后，写出对象、范围、时机及能否恢复。不要从“清除”这个函数名推断它只清缓存。

例如，已确认仅移除此设备的连接配置、不删除提供方数据时：

- 标题：移除此设备上的连接？
- 正文：此设备将停止读取这个来源。提供方的数据会保留。
- 执行动作：移除连接
- 退出动作：取消

如果后端行为不同，上述文案就不适用。可撤销动作通常优先考虑清楚的撤销机制；不可逆且影响重要数据时才需要相应确认。文案技能不授权执行删除。

## 权限和付费

权限说明写明受保护资源的具体用途。先识别应用解释页、用途描述字符串与系统授权框的不同所有者。不要把自定义按钮写成已经授予权限；不要捏造“仅在本机处理”。遵循所用平台当前的权限流程，不把一种系统的按钮布局复制到另一种系统。

价格、币种、周期、资格和续订条款取自实际商品与权益状态。取消交易、等待批准、验证失败、无可恢复项目和恢复成功应有不同表达。打开订阅管理页的按钮不能承诺已经取消订阅。测试文字不需要发起真实购买。
