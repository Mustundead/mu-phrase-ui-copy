# MU LABS 教学示例

这些是围绕个人产品领域编写的假设情境，用来解释方法，不声明当前产品实现或发布状态。使用前核对代码与数据契约。

## TokenBell：部分来源更新失败

前提：来源 A 有旧读数和读取时间；本次刷新失败；来源 B 刷新成功；A 有独立重试。

避免：“全部服务异常，剩余 0%。”

建议 A 卡片：“未能更新。显示 14:20 读取的数据。”动作“重试”。英文：“Couldn’t refresh. Showing data from 14:20.” / “Retry”。保留 B 的成功状态。日期跨天时补足日期和必要时区，不照抄固定时间。

理由：没有把失败误写成归零，没有否定仍然有效的来源，也没有推断故障原因。

## ByteKibble：没有提供剩余额度

前提：提供方响应没有额度字段，只有可识别的订阅名称。

建议：“暂未获取到剩余流量。” / “Remaining data isn’t available.” 不显示“剩余 0 GB”，不从订阅价格估算流量，不把“订阅有效”推导成“流量充足”。如果没有重试操作，正文不要承诺它。

## ByTouch：第一次收藏

前提：收藏列表确实为空，用户可从菜谱详情收藏。

建议标题：“还没有收藏的菜谱”。正文：“在菜谱中点按收藏，就能在这里找到。”英文：“No saved recipes yet.” / “Save a recipe to find it here.” 若页面只有搜索无结果，应改为描述搜索条件，不使用这个空状态。

## KinView：加入请求尚未通过

前提：请求已提交，需要家庭管理员批准；当前没有可用的撤回功能。

建议：“加入请求已发送，等待管理员确认。” / “Request sent. Waiting for an administrator to approve it.” 不能写“已加入家庭”，也不添加没有实现的“撤回”按钮。

## 只给截图的删除弹窗

用户：“把‘是否清空数据’改得短一点。”截图不能说明云端影响。

交付应明确：“需要先确定清除的是哪些数据。如果只清此设备缓存，可用‘清除此设备的缓存？’；不要直接上线这句，直到范围得到确认。”不补写“云端会保留”，不为了缩短删除对象。

## 从事实正确到表达更好

以下仍是教学假设，不代表产品已有这些操作。每例先确认行为，再决定是否采用文字。

### ByTouch：正确但重复

- **上下文与原文：**当前页标题“导出这道菜谱”，文件只包含食材和步骤，不包含照片。正文“导出的菜谱文件会包含这道菜谱的食材和步骤，但不会包含照片。”按钮“导出这道菜谱”。
- **问题：**事实准确，但标题、正文、按钮重复对象，真实限制反而埋在句尾。
- **推荐：**保留标题；正文“文件包含食材和步骤，不包含照片。”按钮“导出”。
- **为什么及不适用条件：**人在这一页已知道导出对象，可用较短动作给限制留空间。如果页面并排展示多道菜谱、按钮脱离标题单独出现，按钮或其可访问名称仍需说出具体对象。

### KinView：短却不知会发生什么

- **上下文与原文：**家庭管理员看到某成员的邀请已过期，当前操作会给同一成员发送一条新邀请。标题“邀请已过期”，按钮“处理”。
- **问题：**“处理”没说发送动作，管理员无法判断是否会再次通知对方。
- **推荐：**标题不变；邻近说明“重新发送后，对方会收到新邀请。”按钮“重新发送邀请”。
- **为什么及不适用条件：**动作与对方会收到什么都在选择前可见。如果当前用户无权发送，或只会打开编辑页，就不能使用此按钮；应按真实动作重写。

### TokenBell：原文已经够用

- **上下文与原文：**标题已经显示来源名称，来源从未读取过数据，页面确有单独读取入口。正文“尚未读取这个来源。”按钮“读取数据”。
- **问题与推荐：**没有需要修的语义问题，保留原样；不用追加“请检查网络”等未证实原因，也不必为了品牌语气加口号。
- **不适用条件：**若已有旧值，应显示旧值和时间；若按钮只打开设置，就不能写“读取数据”。

### KinView：文案与容器一起判断

- **上下文与原文：**相册列表每行都显示完整相册名，并有一个添加动作；窄屏按钮写“在「周末远足与家庭合照」相册中添加照片”，被截断。
- **问题：**强迫按钮独自重复行标题，导致关键动作也难读。
- **推荐：**行内保留可换行的完整相册名，按钮可写“添加照片”；多个同名按钮的可访问名称包含相册名，并检查焦点顺序。若空间仍不足，先调整行布局和换行。
- **为什么及不适用条件：**对象由行标题提供，动作保持短而清楚；若按钮被移到独立工具栏或通知中，没有行标题可依赖，就必须在动作中重新说明目标。
