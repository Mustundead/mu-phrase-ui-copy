# 维护者行为评估

这是维护技能时的重跑方法，不是日常文案任务的额外门槛。给执行者的题目单独保存在 [evaluation-cases.md](evaluation-cases.md)；本页的判据、旧答案和修改意图不要交给执行者。

## 重跑

1. 固定原始请求、状态事实、语言资源、截图或代码片段，记录来源、版本与文件摘要；不要在两次运行之间改输入。题目材料不足时保留不足，测试是否能正确收住结论。
2. 用同一请求在新的上下文分别调用旧包和候选包，保持可用工具、模型请求及可见材料相同。记录请求的模型与思考强度；工具不暴露实际身份时写“未确认”，不能靠配置名推断。
3. 保存两次**原始输出**、读取的文件、实际看过的图、使用的工具、限制与候选包版本。不要先给候选执行者旧答案、诊断或判据。
4. 独立复核每个结果：核对行为后果、来源、旧值与时间、语言、可访问名称和页面空间。若有实现，再用同状态运行画面检查实际行数、截断及受影响语言；只有文案建议就不要写“运行通过”。
5. 记录真实差异与回归，针对已见问题小改；新候选需重跑受影响题。一次好结果不证明跨产品稳定。

## 判据（维护者使用）

| 维护者行为等级 | 可观察证据 |
| --- | --- |
| 未达标 | 编造行为或恢复入口、删掉重要后果、把未知写成零，或把评审越界成产品改动。 |
| 基础可用 | 事实与范围正确，但同一信息在标题、正文、按钮中重复，或只给笼统“精简”而没有可用推荐。 |
| 专业成熟 | 给一个适用于题给状态的推荐；必要事实在决定前可见，动作清楚，空间与语言共同考虑；原文已好时能保留。 |
| 精细打磨 | 在成熟基础上，有相应运行材料时用实际排版与辅助功能证据验证改动，准确写出不适用条件及未测边界。 |

这是**评估执行者的行为**，不是给页面打分。短输出可以成熟；细长报告不能替代事实。每例写具体依据和反例，不数关键词、段落或修改数量。对无运行材料的评审，“未做运行验证”是正确边界，不能因缺设备强迫把它判为未达标。
